# 本使用者的 LoL 分析與資金配置偏好

本文件記錄使用者明確要求，適用本使用者的 LoL 分析，不推廣為其他運動或其他使用者的預設。與共用文件及舊推薦門檻衝突時，本文件優先處理聊天呈現與主觀配置；模型驗證、真實狀態與來源追溯仍保留。

## 以當前比賽內容判斷

- 優先當前版本、實際先發、最近1–2週可比系列、對手強度、BP、對位與局內表現。近期勝負也要解釋勝法與對手品質，不能只數連勝。
- 較早、跨版本或不同陣容的資料降權；無法說明可轉移訊號時排除。不得為湊樣本量讓舊資料主導今天判斷；保留取捨理由，不只挑支持預想方向的場次。
- 預測今天與檢驗過去預測品質分開。校準評估按近期及相近版本／陣容條件分組，揭露樣本量與不確定性；小樣本不宣稱校準成功，也不因未校準而停止領域分析。

## 缺口與數字要說人話

- 不單獨以「證據不足」解釋結論。寫出缺哪個欄位、查核結果、會影響方向／玩法／配置的哪部分，以及仍能支持的判斷；能自行查的先補查。
- 資料齊全但兩隊接近，寫「難分高下」；資料相互矛盾則交代衝突。不把一般賽事不確定性當成缺資料。沒有看 VOD 不算缺口，沿用非影片分析流程。
- 未校準的白話說明是「估計機率還沒有足夠的相近條件預測結果驗證」，只在需要時集中交代一次。
- 主觀情境機率標示為估計；聊天機率通常四捨五入到整數百分比，避免小數點營造精準感。原始快照保留完整精度，所有衍生事件沿用同一分布；四捨五入造成合計差異時簡短說明。不能憑空給機率區間或把敏感度範圍冒充信賴區間。

## 必備核心指標呈現偏好

使用者強烈要求每場分析必須在最顯眼處直觀提供以下核心機率，不需在長文或衍生列表中翻找：
1. **雙方勝負機率（獨贏）**：隊伍 A 勝率 vs 隊伍 B 勝率（對稱呈現雙方數值與公允賠率）。
2. **兩邊各贏一場與兩邊都贏一場以上（總局數門檻）**：
   - **BO3**：兩邊各贏一場／打滿三局（總局數 > 2.5，比分 2:1 或 1:2）的機率。
   - **BO5**：兩邊都贏一場以上／拒絕橫掃（總局數 > 3.5，雙方皆至少破蛋取局）的機率。
   - **BO5 延伸**：兩邊都贏兩場以上／戰滿五局（總局數 > 4.5，比分 3:2 或 2:3）的機率。
3. **單隊受讓局／至少取一局機率**：
   - BO3 各自至少取一局（+1.5 局）。
   - BO5 各自至少取一局（+2.5 局）及至少取兩局（+1.5 局）。
4. **移除冗餘數據原則**：有了兩邊各贏一場（BO3 > 2.5）或兩邊都贏一場以上（BO5 > 3.5）的機率，不額外列出互補的直落二或直落三橫掃機率；比分細節保留在完整比分分布中即可，避免冗餘數據干擾閱讀。

## 每場方向與總資金百分比

使用者表示基本上每場都會參與，主要需要選方向與投多投少。每場交付看好方向、可取得價格的玩法選擇、相對信心、配置及翻轉條件；分開「較可能贏」與「依目前價格較適合選」。不能只因模型未校準就整日一律 0u，也不能為了每場給選擇而捏造優勢。

- 所有注碼以「總資金的 X%」表示，不以 u、當日預算百分比或金額取代。總資金指使用者專門用於投注的資金，以當日開始／本次配置開始時的餘額作共同分母，當日不隨輸贏重新放大。
- 不知道資金金額仍可給百分比，無需為換算金額而阻塞分析。總資金百分比與勝率明確分欄。
- 同時列每場配置、同場多玩法合計及當日總配置百分比；考慮相關玩法的重複曝險。不預設每天必須投完總資金，不因場次增加或前場輸錢追加總曝險。
- 已知當日上限則遵守；未知時可提供明示為暫定的保守配置及合計，邀請使用者調整，不假稱使用者已設定某個上限。配置依證據強弱、實際價格、敏感度與相關性解釋，不從未驗證的微小 EV 差異或 Kelly 公式推導看似最佳比例。
- 未校準模型仍保留 `recommendation_eligible=false` 等真實欄位。另列「主觀資金配置」，其來源是近期領域判斷和使用者參與偏好，不是已驗證的模型優勢；不要把它塞入要求正式模型資格的推薦欄位或竄改驗證器。若需機器可讀輸出，以獨立配置附件保存比賽、玩法、賠率與時間、總資金占比、理由及當日合計。
- 低信心選擇明示低信心並降低相對占比。無法確認事件、結算或價格時，只給條件式方向，該玩法待取價後配置；具體解釋原因，不為填滿每場而發明可成交價格。

## Stake 直接取價的待驗證事項

目前 Odds-API.io 的 `ODDS_API_KEY` 不等於 Stake token；中介 API 未回傳某玩法，不代表 Stake 沒開盤。使用者提到的 `!record` 尚未確認是哪個工具或紀錄，不能寫成已支援功能。

若之後取得合法授權的請求紀錄，先核對 endpoint、查詢內容、token 權限／有效期，以及回應的玩法、盤線、賠率與停盤狀態，再決定是否新增直接取價 adapter。只讀本地安全保存的憑證，不要求在聊天貼 token，不把憑證寫入報告或紀錄；沿用價格快照、事件對應與結算核對。此討論不代表已實作或驗證 Stake 直接取價。
