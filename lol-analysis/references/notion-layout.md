# LoL Notion 報告版型

只有在建立或更新 LoL Notion 報告時讀取本文件。內容與機率規則仍以 `SKILL.md`、`output-template.md` 及共用預測契約為準。

## 版面目標

- 先讓讀者看懂單場結論，再閱讀證據與方法。
- 每場使用相同資訊順序，避免在長段落中尋找勝率、比分、至少一局與盤口條件。
- 核心機率保持可見；只有證據細節、來源與方法可以收合。
- 所有對外文字只顯示官方／通用隊伍縮寫；完整正式隊名留在 canonical artifact，不放進 Notion 標題、正文、表格或投注選項。

## 每場固定順序

1. `時間｜賽區・{A縮寫} vs {B縮寫}` 標題。
2. 預測 callout：最可能比分、系列賽勝率、模型信心度、決策狀態與注碼。
3. 完整精確比分分布。
4. 獨立的「至少拿一局」四欄表格。
5. `預測方為什麼佔優`，使用 1–3 個可掃讀重點。
6. `對手的爆冷路徑`，使用 1–3 個可掃讀重點。
7. `跨市場比較`：先列賽制別必要盤線的 priced／unavailable／unmapped／failed，再以表格列出至少三個最高順位已定價候選（不足三個就列全部）。BO3 必含 ML、絕對值 1.5 讓分、O/U 2.5；BO5 必含 ML、絕對值 1.5／2.5 讓分、O/U 3.5／4.5。完整雙邊計算保存在 artifact，不必把所有負 EV 選項塞進行動端頁面。
8. 盤口裁決或賽前閘門 callout：最後玩法、當前價、觸發價、待確認資訊與注碼。最終玩法由所有必要市場一起比較，不預設 ML 優先。
9. 證據連結、H2H 使用方式與資料缺口放入 toggle。

比分分布後必須立刻顯示以下結構，不得改成內文句子或藏入 toggle：

```markdown
<table fit-page-width="true" header-row="true">
	<tr color="green_bg">
		<td>至少拿一局</td>
		<td>{A縮寫}</td>
		<td>{B縮寫}</td>
		<td>雙方皆至少一局</td>
	</tr>
	<tr>
		<td>模型機率</td>
		<td>{A 至少一局%}</td>
		<td>{B 至少一局%}</td>
		<td>{雙方皆至少一局%}</td>
	</tr>
</table>
```

跨市場候選使用以下固定欄位，讓讀者能直接看出非 ML 玩法是否被比較；`玩法` 一律用隊伍縮寫：

```markdown
<table fit-page-width="true" header-row="true">
	<tr color="gray_bg">
		<td>玩法</td>
		<td>模型機率</td>
		<td>當前價</td>
		<td>最低價</td>
		<td>EV_adj</td>
		<td>閘門／結論</td>
	</tr>
	<tr>
		<td>{例如 A縮寫 +1.5}</td>
		<td>{%}</td>
		<td>{@十進位價}</td>
		<td>{十進位價}</td>
		<td>{%}</td>
		<td>{通過；立即可打／等價／避開}</td>
	</tr>
</table>
```

## 機率推導與隊伍順序

- 隊伍 A 至少一局＝`100% - 隊伍 A 被橫掃機率`。
- 隊伍 B 至少一局＝`100% - 隊伍 B 被橫掃機率`。
- 雙方皆至少一局＝`100% - A 橫掃 B - B 橫掃 A`，也等於全部非橫掃精確比分之和。
- BO3 與 BO5 使用相同邏輯，不另建或手填衍生機率。
- 比分分布、至少一局表與簡表必須使用同一隊伍順序。對外表格只寫官方／通用縮寫，不使用完整正式隊名，不加「主隊／客隊」，也不得留下「隊伍 A／隊伍 B」占位字樣。

## 顏色與資訊層級

- `blue_bg`：一般預測方向。
- `yellow_bg`：最接近價值、需要盯價或等待單一資訊。
- `orange_bg`：高波動或模型分歧明顯。
- `red_bg`：關鍵先發未定、硬阻擋或完全避開。
- `green_bg`：只用於「至少拿一局」表頭，讓必要衍生機率易於辨識。
- `gray_bg`：一般盤口說明、證據或方法。

不要只用顏色傳達結論；callout 內仍須寫明決策狀態、原因與觸發條件。

## 多場報告

- 方法、資料來源與限制放在所有單場卡片之後，使用 toggle 收合。
- 置底 `簡表總結` 仍依共用最終輸出契約只出現一次，並使用單一「至少一局機率」欄逐場列出 `{縮寫 1} {%}`、`{縮寫 2} {%}`、`雙方 {%}` 三行。
- 簡表不得只保留「雙方皆至少一局」，也不得使用完整正式隊名、主隊／客隊或隊伍 A／B。三項放在同一格並以 `<br>` 分行，避免增加欄數造成 Notion 與行動端難讀。
- 發布前逐場檢查三項至少一局機率均存在、帶 `%`、隊伍順序一致，且通過 `shared/validate_probabilities.mjs`。
