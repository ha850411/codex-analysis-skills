# 陣容變動與基準稽核

適用 LCK CL 等二級聯賽、已知換人，以及既有報告的擴寫／重排。保留隊伍層級預測交付；以下稽核不能變成任意拒絕建模的理由。

## 證據與模型必須對齊

- 隊伍識別包含聯賽與梯隊，T1A 與一軍 T1 不共用強度或選手資料。歷史交手逐筆保存日期、賽事、階段及已知實戰五人；跨國賽與例行賽不能統稱同一個夏季賽。歷史五人未知就標未知，不能推定與本場相同。
- 已查得的升降隊、換人與實際輪替要保留在新快照。只有新且具體的出賽證據能解除缺口；不能因重寫報告把預估名單改成 established，或換成另一位選手卻不附來源。選手改名需身分映射證據。
- 每項主結論標明是「模型已使用的輸入」、「有證據但未建模的風險」或「待驗證假設」。只有系列比分的 Elo 不能宣稱已量化 BP 深度、物件控制、風格克制或換人效果。百分比統計須有樣本數、時間窗與來源內容；有網址不等於內容支持主張。
- 已知歷史陣容不同但隊伍模型仍合併計算時，保存受影響的 history event IDs 與來源。不能只在正文說 H2H 打折，卻暗示數值已調整；也不能事後刪掉敗局。陣容可比性過濾或權重先作 candidate，雙方同一標準並以配對樣本外比較決定是否採用。

## 可重播敏感度

隊伍基準遇到已知陣容變動時，先重播原模型，再對**每一筆**納入的系列做 leave-one-series-out；避免只移除支持事後贏家的場次。使用：

```bash
python3 lol-analysis/scripts/audit_baseline_sensitivity.py \
  --history <history.json> --event <event.json> \
  --forecast <forecast.json> --output <new-run/sensitivity.json>
```

工具只產生隔離的資料敏感度實驗，不改正式快照。輸出勝方是否翻轉、勝率範圍、影響最大的系列及每筆移除結果。這個範圍不是信賴區間，翻轉次數不是命中率；沒有翻轉也不代表已校準。

若勝方翻轉，仍交付原主分布的勝方與勝率，並明說「方向對樣本選擇敏感」。不能從實驗中挑一個勝率當新主結論。缺 history／模型或重播不一致時列為溯源失敗，補找原產物；不得以同名 model_version 當作相同模型，也不得改寫歷史快照。

## 重寫與賽後固定稽核案例

擴寫／表格化先比對舊快照的 event identity、主分布、五項信心評分、名單分類和 missing_data。純呈現修改沿用原數據；有新證據才另建完整快照，記錄 supersedes 與更動理由，重跑驗證。統計、名單與因果敘述也要查核，不能只驗機率加總。

- 輸入 A：舊快照寫 ADC 實際輪替、上路 Haetae，重寫後無新證據卻改 Guardian／固定五人且提高先發確定度。裁決：內容與證據不一致，退回重寫；不得當成證據改善。
- 輸入 B：H2H 含六月國際賽，摘要稱「夏季近四次全勝」。裁決：修正範圍標籤，逐筆核對；若有進模型，建立新輸入重算，不能只改摘要。
- 輸入 C：同場有多個 event_id 或純文字變體。裁決：以聯賽、日期、階段、雙方映射同一事件；各版本留存，勝方命中按事件／預先選定快照計一次。無發布順序證據時並列版本，不猜使用者收到哪份。
- 輸入 D：Elo 算術通過、主文卻聲稱控龍率超過 60% 而無統計來源。裁決：刪除無證據的主張或補證；算術通過不代表內容驗證通過。
