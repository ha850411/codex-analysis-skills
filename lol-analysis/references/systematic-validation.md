# 跨日驗證與決策診斷

新分析者情境與系統性檢討使用。延續共用 postmortem 契約、現有參數敏感度及使用者配置偏好；不新增隊伍特例、不因昨日輸贏選權重，也不改正文模板。

## 接續同一個改善實驗

先定位既有 `history/factor-registry.json`、最近 `postmortems` 的 cohort、candidate-plan 和實際快照；目前本機位於 `.automation-state/lol/history/`，找不到時再查報告歸檔，不初始化空帳本假裝沒有歷史。搜尋已知根目錄含隱藏檔，事件先去重、先選發布版本再接結果。

對上一輪聲稱修正的問題逐项回答：規則何時生效 → 本次是否執行 → 哪個輸入／決策實際受影響 → 是否有未見結果的配對驗證。可能裁決為：未執行、工具只驗算未驗語意、已執行但數值效果未驗證、已有退步證據、合理變異。附上產物定位。不要把最後一類當作所有錯誤的解釋，也不把前四類全稱為「沒考慮反證」。

明確區分三層：

- **研究程序**：名單、版本、對手阻斷、正反證核對可立即改善查核；完成不代表已有預測增量。
- **實際入模假設**：分析者手選的情境權重與條件率屬實驗機率。保存其映射方法／版本、支持與反證；不能只因敘事完整、來源多、重播成功就視為校準。若每場仍由分析者重新判斷數字，標明判斷程序與不可重現幅度，不能稱為固定係數模型。
- **數值候選因子**：沿用穩定 factor_id，candidate 的新加成／懲罰／權重映射只進隔離挑戰版。既有一般 BP 研究與新增數值因子分開記；若候選機制其實已在對外情境影響數字，記錄這個實際用途與 experiment 狀態，不能僅憑 registry 的 `used_for_prediction=false` 聲稱從未使用。

## 用增量效果定位問題

保留完整已發布事件母體，含命中、未命中、未終場與缺預測，不只挑受爭議場次。原情境與其內嵌比分基準按同事件、同 cutoff、同賽制配對，使用共用 `evaluation.py`／CLI 計分：勝方、精確比分、Brier、log loss、coverage；另列每場從基準到情境的方向／幅度及機率品質差值。

按模型版本、賽區、BO3／BO5、pre/post-draft 分層，並以賽前可觀察的機制觸發條件列出命中與失敗對照。小樣本的 LPL 連錯等訊號只能決定優先研究範圍，不能生成賽區扣分或反買規則。歷史只足以支持「查這個問題」時，不聲稱已確立共同因果。

價格決策獨立計分，保存實際推薦方向、價格、配置與來源；沒有價格／配置的 Over 或至少一局不是下注命中。模型看好勝方而配置反向落敗，兩者都如實列出。沒有成交證據只算建議方案的條件損益，不計實際 ROI。

原比分基準與原情境的比較不是新版 skill 的驗收。開始數值 challenger 前，在 candidate-plan 鎖定具體改動、程式／提示版本、適用條件、同一證據包、截止、測試母體與否決条件；每個適用事件在賽前實際保存兩份預測、參數與差異。寫了計畫但未產生配對快照，forward sample 就是 0。

已用來找錯或選參數的比賽列開發集。改過候選就保留試驗履歷、另留未看過區段；不能每天換假設卻合稱同一新版。用同一截止資料的 add-one／消融檢驗增量，依共用升版門檻裁決；工程修正、決策診斷、預測準確度分別驗收。

若修改後信心普遍下降或主勝率大量靠近50%，回查 `forecast-fallback.md` 的逐項評分與證據變化，分清真實資料／模型問題與重複懲罰。改善仍看同一完整母體的勝方、比分及機率品質；平均信心降低、建議變少、語氣保守都不算成功，也不為維持高信心反向補分。

## 鎖定後檢查价格優勢

`audit_decision.py` 僅接收已可重播的 LoL 情境快照，以及人工核對事件／隊序後的同 book、同時點兩側獨贏快照：

```json
{
  "forecast_id": "原快照 ID",
  "event_id": "原事件 ID",
  "market": "series_ml",
  "participants": ["原第一隊", "原第二隊"],
  "decimal_odds": {"a": 2.35, "b": 1.60},
  "retrieved_at": "2026-09-18T04:18:30Z",
  "source_url": "可追溯的原價格來源",
  "book": "Stake",
  "entry_floor": {"a": 2.10}
}
```

`entry_floor` 可省略；有給進場底價就須檢查。不得直接把 provider home/away 當作模型 a/b。工具支援無和局 BO3／BO5 系列獨贏，其他玩法不能借用其結論。

檢查內容：主機率、損益兩平率、同快照去水市場參考、原單項壓力範圍、聯合壓力範圍、兩端完整比分與參數見證，以及當前價／進場底價是否跨過零 EV。市場僅作鎖定後比較，不回灌主機率。

聯合診斷沿用原 audit 的尺度：各情境所有節點共同移動 −0.05／0／+0.05，可同時發生；權重在原值 ±0.10 與 [0,1] 交集內、合計1。有限 rate 組合搭配有界權重的極值可精確求得；非法 rate 候選跳過並列明，不截斷補值。這不是全部可能誤差的界限，也不涵蓋漏掉的機制或任意局間變化。

若單項測試看似都正 EV，聯合測試卻跨零，原「最低測試勝率仍高於門檻」的論證就不足。說明哪些同時成立的假設會令價格優勢消失；不以診斷端點設新公允價或直接改買對手。聯合測試仍正 EV 也不能證明可獲利。延續使用者每場方向與實質配置偏好，但不能把主觀參與配置稱作已驗證優勢。

任何固定率的局數限制，仍依 `analyst-scenarios.md` 標示。新增條件樹支援只表示引擎可表達局間依賴；實際輸入仍固定率，就不能說已把 Fearless／局間調整量化。
