# 閱讀與輸出契約

## 聊天摘要

結論 → 最多三項依據 → 最大翻轉條件與狀態 → 完整報告連結 → 唯一置底簡表。

LoL 採結果優先的專用順序：結論 → 詳細預測結果與價格決策 → 精簡依據與翻轉條件 → 狀態與附件 → 唯一置底簡表。欄位及模式差異見 `../../lol-analysis/references/output-template.md`；此呈現規則不改其他運動的預設。

CS 的 full 聊天直接呈現完整分析，使用 `../../cs-analysis/references/output-template.md` 的結果、逐圖與證據要求，不套用「最多三項依據」上限；quick、veto 更新、live 與 daily-summary 按該文件取適用內容。正文可有明細表，單一 quick 可不附總結表；此例外只適用 CS。

需要置底簡表時固定五欄：比賽（含 UTC+8 時間）、核心預測、模型信心度、建議、核心風險。核心預測分別顯示勝方與勝率、比分眾數與其機率；CS 的聚焦更新可改放使用者所問市場及其機率。信心度明示是證據品質評分。

## 完整報告

結論 → 關鍵比較 → 領域分析 → 結果分布及替代情境 → 市場決策 → 來源與限制 → 唯一置底簡表。

LoL 完整報告同樣先呈現結果分布、衍生機率與市場決策，再放精簡領域分析、替代情境及來源限制；逐局研究與執行稽核另存附件。共用數值與驗證契約保持一致。

CS 完整報告沿用其 full 聊天的內容與順序，另附研究明細；聊天本身須足以理解預測、逐圖判斷及價格決策，不能把必要內容只放附件。

- 比較表預設3–5欄；名單、逐圖資料與長理由拆成段落。領域必要機率仍保留在正文和 JSON。
- 不用字數比率判斷完整性；必要章節及適用問題須有答案、缺口或有理由的 not-applicable。
- 不預填主推、正注碼或紅綠強弱暗示；建議來自市場後的獨立驗證決策。
- 同一數值由 canonical JSON 渲染，不讓聊天、Notion、口播自行估算。四捨五入只改顯示；完整精度保存在 JSON。正文總和以完整值驗證。
- 勝方與比分眾數可能方向不同，必須說明；並列峰值揭露為並列，不能假稱唯一最高。
- 精確比分是單一結果機率，不能用模型信心度代替它。NBA／MLB 均值不稱作最可能比分。
- 基準版、實驗版與缺資料狀態放在讀者能看到的位置；不要藏在腳註。
- Notion 窄表保留表格，長段落可轉卡片；紅隊完整 finding、理由與裁決留在 JSON，正文只寫影響結論的修正。
- 所有連結、來源與附註置於簡表前，表格之後不再添加內容。

既有 pipeline JSON 的 probability_groups 保留百分比與原 schema；其渲染器同樣採五欄摘要。新共用 JSON 使用 fraction；不同入口不得混用單位。
