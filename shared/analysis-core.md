# 賽事分析共用入口

適用所有 `*-analysis`、互動與排程。

## 規則歸屬

- `forecast/contract.md`：資料時序、主分布、快照、基準／實驗模型、機率單位及工具介面。
- `forecast/report-template.md`：聊天與完整報告的唯一排版契約。
- `postmortem-improvement.md`：因子生命週期、配對評估、改善與升版證據。
- 各技能的 source-priority／domain-analysis：領域查核、來源與結算差異。
- `markets/collection-contract.md`：機率鎖定後的價格取得、重試、來源與市場覆蓋。

領域指引不得直接更改共用數值、時間或排版契約。舊版專用 schema 和 CLI 保留相容驗證；只有標為 legacy 的流程才沿用舊契約，不能把任意舊 JSON 當成 v2。

## 流程

確認賽事集合 → 查核證據與截止時間 → 建模／情境 → 鎖定並保存預測 → 取得市場及獨立決策 → 驗證 → 渲染。

- 繁體中文、台灣時間；易變資訊必須當次查核。
- 單一追問用 quick，單場用 full，整日用 daily-summary，檢討用 postmortem。精簡只減少文字，不減少數字驗證與快照保存。
- 勝方命中優先、比分次之；機率品質、可用率與覆蓋率同時回報。降低信心、注碼或少預測難場不算改善。
- 有價格才能做可成交價比較；無價保留模型與報告，清楚標記缺價原因及 0u。
- 模型信心度為五項證據品質評分，與結果機率分開。多場逐場獨立計算；禁止把日報層級分數複製到每場。
- 新預測的聊天與完整報告皆結論置頂、單一五欄簡表置底。所有來源、連結、補充均置於簡表之前。

## agy 與外部動作

使用者明確要求 agy、agy-cli、紅隊或模型互審時才讀 `../prediction-pipeline/SKILL.md`，依既有設定告知實際模型後執行；一般分析不顯示模型計畫或額外啟動模型。紅隊提供查核意見，主模型逐項裁決；只有新證據或重現錯誤才能改數字，修改後重建所有衍生結果。

查核及本地驗證可直接進行。Notion、郵件與其他外部發布沿用使用者授權與排程設定；僅有 `NOTION_AUTO_PUBLISH=1` 不新增互動請求的發布授權。測試與回測不得對外發布，也不得呼叫真實盤口 API。git-commit-push 與目前模型設定不因本重構改變。
