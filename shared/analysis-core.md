# 賽事分析共用入口

適用所有 `*-analysis`、互動與排程。

## 規則歸屬

- `prediction-methodology.md`：新預測的證據取捨、模型適用性、反證與敏感度；產生或更新機率時讀取，純格式整理或解釋既有數字不重跑研究。
- `forecast/contract.md`：資料時序、主分布、快照、基準／實驗模型、機率單位及工具介面。
- `forecast/report-template.md`：聊天與完整報告的唯一排版契約。
- `report-storage.md`：Gemini／Codex 共用的報告自動分類、版本保存與本地索引；建立或更新報告時讀取。
- `postmortem-improvement.md`：因子生命週期、配對評估、改善與升版證據。
- 各技能的 source-priority／domain-analysis：領域查核、來源與結算差異。
- `markets/collection-contract.md`：機率鎖定後的價格取得、重試、來源與市場覆蓋。

領域指引不得直接更改共用數值、時間或排版契約。舊版專用 schema 和 CLI 保留相容驗證；只有標為 legacy 的流程才沿用舊契約，不能把任意舊 JSON 當成 v2。

使用者當次指示與已明確保存的個人偏好優先於 skill 預設；專用例外只套用對應運動及流程。沿用現有輸出模板、欄位、順序與呈現方式；研究改善放入既有分析／風險／來源位置或本地附件。模板變更先提出具體差異，取得使用者確認後才修改，不因重構或換模型自動改版。

## 流程

確認賽事集合 → 查核證據與截止時間 → 建模／情境 → 鎖定並保存預測 → 取得市場及獨立決策 → 驗證 → 渲染 → 自動分類歸檔 → 交付。

- 繁體中文、台灣時間；易變資訊必須當次查核。
- 單一追問用 quick，單場用 full，整日用 daily-summary，檢討用 postmortem。精簡只減少文字，不減少數字驗證與快照保存。
- 勝方命中優先、比分次之；機率品質、可用率與覆蓋率同時回報。降低信心、注碼或少預測難場不算改善。
- `full` 與 `daily-summary` 在鎖定機率前完成各領域必要查核，依本場機制選讀細節；日報只壓縮呈現，不把逐場研究換成通用敘事。`quick` 沿用有效快照，只有新證據或新問題需要時才更新受影響部分。
- 對可自行查到的賽事、名單與規則先查核；非關鍵缺口用具名假設或既有降級路徑繼續。無法辨識賽事、結算範圍或缺口會改變主要問題時才釐清，同時完成不受影響的場次。
- 驗收分成來源內容正確、模型實際使用、數值／快照一致三部分。CLI 通過只能證明其驗證範圍，不能代替領域分析，也不證明參數已校準。
- 每次新建或更新報告，依 `report-storage.md` 呼叫 `report_archive.py save`，以運動、用途、目標台灣日期保存報告與當次附件並更新索引。quick 新預測、full、日報、live、賽後檢討皆適用；保留排程指定輸出與 canonical record，再建立不可覆寫的封存版本。失敗如實記錄，不虛報已歸檔；歸檔不改模板或評分資格。
- 盤口收集必須優先載入根目錄 `.env`（確保取得 `ODDS_API_KEY` 等變數），不得在未檢查 `.env` 檔案前逕行判定缺金鑰或放棄取價；機率鎖定後一律依 `markets/collection-contract.md` 執行真實收集。
- 有價格才能做可成交價比較；無價保留模型與報告，清楚標記缺價原因及 0u。
- 模型信心度為五項證據品質評分，與結果機率分開。多場逐場獨立計算；禁止把日報層級分數複製到每場。
- 新預測的聊天與完整報告皆結論置頂、單一五欄簡表置底。所有來源、連結、補充均置於簡表之前。

## agy 與外部動作

使用者明確要求 agy、agy-cli、紅隊或模型互審時才讀 `../prediction-pipeline/SKILL.md`，依既有設定告知實際模型後執行；一般分析不顯示模型計畫或額外啟動模型。紅隊提供查核意見，主模型逐項裁決；只有新證據或重現錯誤才能改數字，修改後重建所有衍生結果。

查核及本地驗證可直接進行。Notion、郵件與其他外部發布沿用使用者授權與排程設定；僅有 `NOTION_AUTO_PUBLISH=1` 不新增互動請求的發布授權。測試與回測不得對外發布，也不得呼叫真實盤口 API。git-commit-push 與目前模型設定不因本重構改變。
