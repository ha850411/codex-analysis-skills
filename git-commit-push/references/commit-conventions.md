# Git Conventional Commits 語意化提交訊息規範指南

本指南定義遵循 **Conventional Commits** 標準之 Git 提交訊息（Commit Message）結構、類型定義、繁體中文動詞庫與撰寫範例，確保專案版本歷史清晰、易讀且與自動化 CI/CD 工具鏈高度相容。

---

## 📌 基本結構

每一次提交訊息應由「**標題行**」、「**空行**」與「**詳細內文**」組成：

```text
<type>(<scope>): <純繁體中文簡要說明>

- <模組或子項目>: <具體修改內容與設計原因>
- <模組或子項目>: <具體修改內容與設計原因>
- <補充說明/重要影響/注意事項>（選填）
```

---

## 🏷️ 類型定義（Conventional Commits 標準對照）

| 類型前綴 (Type) | 說明 | 適用場景 |
| :--- | :--- | :--- |
| **`feat`** | 新增功能 (Feature) | 新增模組、全新頁面、新增 API 端點、新增分析技能 |
| **`fix`** | 修復錯誤 (Bug Fix) | 修復程式錯誤、邏輯異常、崩潰、資料不一致 |
| **`refactor`** | 程式碼重構 (Refactor) | 不影響外部行為的代碼整理、架構優化、簡化重複邏輯 |
| **`docs`** | 文件更新 (Documentation) | 新增或修訂 README、SKILL.md、架構圖、參考文件或註解 |
| **`test`** | 測試相關 (Testing) | 新增單元測試、整合測試、修正既有測試案例 |
| **`chore`** | 雜項維護 (Chore) | 依賴升級、構建設定、Git 設定檔（.gitignore）、排程腳本調整 |
| **`style`** | 格式排版 (Code Style) | 空白字元、排版縮排、程式碼格式化（不影響邏輯） |
| **`perf`** | 效能優化 (Performance) | 提高執行速度、降低記憶體或網路頻寬消耗 |
| **`ci` / `build`** | 持續整合與建置 | GitHub Actions、CI 工作流程、建置工具鏈設定 |

## ✍️ 純中文動詞庫建議

在撰寫標題與內文時，建議使用語意精準的繁體中文動詞：

| 類別 | 推薦動詞 |
| :--- | :--- |
| **新增與建立** | 新增、建立、引入、整合、擴充、補齊 |
| **修復與修正** | 修復、修正、解決、排除、校正、防止 |
| **重構與優化** | 重構、最佳化、簡化、調整、抽離、拆分、改善 |
| **更新與維護** | 更新、升級、同步、相容、清理、移除、棄用 |
| **驗證與防護** | 驗證、檢查、防範、限制、斷言、攔截 |

## 💡 優良 Commit 訊息範例對照

### ✅ 優良範例 1：新增功能 (feat)
```text
feat(lol-analysis): 新增英雄聯盟賽前名單與版本證據閘門

- lol-analysis: 引入 forecast-evidence-gates 規範與自動化驗證腳本
- scripts: 新增 validate_forecast_evidence.mjs 用於自動檢驗名單時效
- evals: 補充跨賽區多戰隊名單變更之回溯測試案例
```

### ✅ 優良範例 2：修復問題 (fix)
```text
fix(automation): 修正排程腳本未正確捕捉子程序崩潰之異常

- predict_next_day: 補齊子程序非零結束代碼之例外捕捉機制
- test_automation: 新增模擬引擎崩潰的測試案例，確保重試邏輯正常
- common: 統一錯誤訊息輸出格式並記錄於日誌中
```

### ✅ 優良範例 3：文件與維護 (docs / chore)
```text
chore(repo): 忽略本機暫存目錄並更新技能清單說明

- gitignore: 將 .tmp/ 臨時測試目錄加入忽略清單
- README: 補充預測管線與各運動項目技能之快速入口連結
```

## 🚫 常見不良範例（需嚴格避免）

1. ❌ **夾雜英文說明或無意義標題**：
   - 錯誤：`fix: update some files and fix bug`
   - 錯誤：`wip`
   - 錯誤：`Update SKILL.md`
   - 正確：`fix(valorant): 修正地圖池機率權重計算異常`

2. ❌ **使用純中文自訂前綴（導致 CI 工具無法解析）**：
   - 錯誤：`功能(lol-analysis): 新增名單檢查`
   - 錯誤：`修復(mlb): 修正先發投手名單`
   - 正確：`feat(lol-analysis): 新增賽前名單檢查機制`
   - 正確：`fix(mlb): 修正先發投手名單取得邏輯`

3. ❌ **缺少具體原因與影響範疇**：
   - 錯誤：`修改程式碼`
   - 正確：`refactor(shared): 抽離共用機率驗證邏輯至 validate_probabilities 模組`

4. ❌ **標題過於冗長或含句號**：
   - 錯誤：`feat(mlb): 今天我們新增了先發投手的近期五場對戰數據統計以及牛棚負擔天數計算的功能。`
   - 正確：`feat(mlb): 新增先發投手近況與牛棚負擔天數計算`
